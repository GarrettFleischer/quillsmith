## Cursor Cloud specific instructions

- Package manager/runtime is **Bun** (lockfile is `bun.lock`). Bun lives at `~/.bun/bin/bun` (added to `PATH` for login shells via `~/.bashrc`); use a full path if it's not on `PATH`. Standard scripts live in `package.json` and `README.md`.
- Run the app with `bun run dev` (Next.js 16 + Turbopack, http://localhost:3000). It's local-first: the SQLite DB at `data/quillsmith.db` (gitignored) is auto-created, migrated, and seeded on the first request via `getDb()` — no manual DB setup needed.
- Do **not** rely on `bun run db:seed`: it aborts under Bun with a `better-sqlite3` NAPI fatal error (the `bun -e` path). It is unnecessary because startup auto-seeds; ignore it.
- `bun run typecheck` is clean. `bun run lint` runs but currently reports pre-existing errors/warnings in the source (mostly `react-hooks` rules) — these are not environment issues.
- AI features (Expand/Coach/chat/summaries) call OpenRouter. The key lives in the `OPENROUTER_KEY` secret. `openRouterChat()` reads `settings.openrouterApiKey || process.env.OPENROUTER_API_KEY` at request time, so start the dev server as `OPENROUTER_API_KEY="$OPENROUTER_KEY" bun run dev` to power server-side calls. Note the AI *UI* gates on the settings key (`hasApiKey = Boolean(settings.openrouterApiKey)`), so to enable the in-app AI buttons you must also paste the key once in Settings; the env var alone powers the API but leaves the UI showing "add a key".
- Model policy: use a **free** model for every task (the provided key has a $0 spend limit, so paid models return `403 Key limit exceeded`, which the app surfaces as a clean SSE `error` event). Set it in Settings → default model. Recommended pin: `nvidia/nemotron-3-super-120b-a12b:free` — fast (~1s), 262k context, good prose, reliable tool-calls in single-shot. `openrouter/free` (an auto-router) is the availability fallback but routes to a random free model per call. **Free-model availability on OpenRouter fluctuates** (e.g. `openai/gpt-oss-20b:free`, `deepseek-*:free`, some `glm`/`gemma` free tiers go 404/"provider error" intermittently) — if the pinned model errors, re-check the live list at `GET /api/v1/models` and repin.
- Reliable AI paths with free models: single-shot calls are reliable — the Chat panel **Expand** button for prose (streams into the manuscript), **Generate beats from summary** (Beats panel), Coach density/checks/critique. Chapter/Overview chat set summary/beats via the Needle layer (see below), so the main model never emits native `tool_calls`. The current-chapter tools also ignore any model-supplied `chapterId` in favor of the open chapter (`ctx.chapterId`), and `runAgentLoop` keeps a `MAX_ROUNDS` cap as a backstop. Keep the multi-step **Craft pipeline** (Settings → craft toggle) **off** with free models — a step can return a meta-comment like `"(No additional text needed)"` or, under `openrouter/free`, a content-safety model's `"User Safety: safe"`; single-call prose (craft off) still uses full codex + summary + beats context.
- Top-down authoring UI (top-down order = act summary → chapter summaries → beats → codex → prose): the Summary rail edits both **Act summary** and **Chapter summary** (autosaves via the `summarize-chapter` `PUT`); act/chapter titles and the chapter goal are edited inline in the manuscript header; beats are reordered by **dragging the grip handle** (pointer-based, mouse+touch); `Generate beats from summary` calls `POST /api/ai/generate-beats`. Non-AI flows (create novel, premise/genre/tone, structure, Codex, export) work fully without a key. The editor `/` slash-menu is legacy/finicky — prose entry is the Chat panel **Expand** button.
- **Extract codex from selection**: highlight prose in the editor → the selection bubble menu's "Extract codex" button (`chapter-editor.tsx` → `workspace` store `openExtract`) opens a review modal (`codex-extract-modal.tsx`, portalled to `document.body` so the sidebar's `panel-enter` transform can't trap the overlay) that proposes new/updated Codex entries from the highlighted passage. `POST /api/ai/extract-codex` takes `{novelId, text}` (falls back to a plan digest if `text` is omitted, but there's no full-novel UI trigger — it mostly echoed existing entries, so it was dropped). Structured-JSON endpoints (`extract-codex`, `generate-beats`) pass `reasoningEnabled: false` + a `maxTokens` cap to `runAgentLoop`: the pinned free model is a reasoning model that otherwise burns tokens on chain-of-thought (JSON extraction went from ~72s to ~2–8s once reasoning was disabled). Free models extract conservatively and vary run-to-run — an empty run is retryable.
- The Chat panel's quick-action buttons show **only favorited Actions** (star an Action in the left Actions tab; toggles `slash_commands.favorite` via `setCommandFavorite`). With no favorites the row is hidden by design — that is expected, not a bug.
- **Needle 2 is the tool-calling layer (always on, required — no toggle).** All agentic tool use (Chapter chat, Overview chat) goes through a local [Needle 2](https://cactuscompute.com/needle) sidecar: the big model describes ONE action in plain language, Needle (a 45M tool-calling model) emits the concrete call, and `executeTool` runs it (`src/lib/needle-loop.ts` + `src/lib/needle.ts` + `services/needle/server.py`). The main model therefore never needs native function-calling — prose (`/api/ai/generate` Expand/Rewrite/Layer) is written straight from the in-context curated codex (no tools passed), and extraction/coach/summaries just return text/JSON.
- **The Needle sidecar must be running** for chat: `pip install --break-system-packages cactus-needle` (installed by the update script; heavy — pulls JAX, then caches the ~14MB engine under `~/.cache/cactus-needle`), then start it with `python3 services/needle/server.py` (listens on `127.0.0.1:8787`; override via `NEEDLE_PORT`/`NEEDLE_URL`; first start warms the model ~10s). If it's down, chat/overview return a clear "start the sidecar" error and the rest of the app is unaffected. Sidecar notes: it uses `agent.complete(text, max_new_tokens=1024)` (256 truncates longer summary args → "token budget exhausted"); the loop executes only the FIRST call Needle returns per plan line (so a description can't fan out into an unwanted `propose_chapter_rewrite`), caps rounds, and treats a repeated plan line as DONE. Needle `confidence` reads very low even on correct calls, so the loop does not gate on it.
